# 南京骑行辅助规则

> 2026-10-16 更新：手机 0.4.4 已移除自动限摩区域和桥隧名单检查，路线页无需限摩确认，不显示限摩图层。高架 / 高速 / 轮渡偏好及自定义避让区继续生效。下文记录历史网关及旧版客户端规则，不适用于当前 iOS 导航流程；当前使用步骤见 [iOS SDK 接入](IOS_AMAP_SDK.md)。

2026-10-16，按用户确认的 **南京郊区登记号牌** 开发。
这是普通驾车算路上的辅助筛选，不是高德专用摩托车导航，不提供整条路线可以通行的保证。

## 历史流程

1. 旧版首页或路线页进入“南京骑行”。可调整路线偏好、避让区域及途经点。
2. 可以在地图逐点圈出最多 4 个避让区域，每区 3–16 个顶点；支持凹多边形。
   可添加最多 6 个按顺序经过的途经点，设置保存在手机。
3. iPhone 向自己的 HTTPS 网关发送 `motorcycle_options`。郊区登记、外地和未知类型自动应用
   摩途官网南京禁外摩区域；主城区登记类型不套用该区域，已收录桥隧和自定义区域仍检查。
   自定义区域和途经点从 WGS84 转 GCJ-02，摩途原始 GCJ-02 图层不再转换。
4. 起点、终点或途经点位于适用禁区内时直接提示冲突。穿过摩途完整区域、自定义避让区或
   命中已收录禁行通道的候选被剔除，包含线段穿区及边界接触。第一次候选全部冲突时，
   最多尝试一次同偏好的其他算路策略；两次共享 8 秒期限，不降级为无约束汽车算路。
5. 路线地图以橙色显示适用禁外摩区；主城区登记类型下该区域以灰色参考显示。
   路线页显示“规则覆盖不完整”、核对日期和来源。核对路线并打开确认开关后才能出发。
   更换路线或设置、重新规划都会清除该确认。预览超过两分钟或起点漂移超过 120 米，需要重新核对。
6. 导航中持续显示规则覆盖提示。偏航重算使用相同登记类型、偏好和避让区域，
   仅保留尚未到达的途经点；重算后的新路线仍需骑行者核对。
7. 若重算或路况请求得到已收录的禁行冲突、规则检查缺失或不匹配，取消旧指引并发送
   导航取消状态到车机，回到路线页显示原因；不继续以旧指引掩盖该错误。

“已到达途经点”采用距离不大于 30 米、水平精度不大于 20 米、时间差不超过 10 秒的定位。
只按顺序移除下一个点，不能因靠近后续点而跳过前面的点。路况刷新继续使用已接受路线当时的
完整起点与途经点基线，避免改变路线后错误套用路况偏移。

演示导航仍是独立的济南模拟路线，不发送南京骑行设置，也不作为规则正确性的验证。
ESP32 的 BLE 数据格式和固件没有修改。

## 历史规则覆盖与限制

规则版本：`nanjing-2026-10-16.2`，资料核对日期：2026-10-16，始终返回 `partial / review_required`。

| 检查对象 | 实现与限制 |
| --- | --- |
| 已收录过江通道 | 精确道路名称及有限别名匹配，涵盖二、三、四、五桥相关名称，应天大街、定淮门、燕子矶、新生圩、建宁路通道 |
| 南京长江大桥 | 当前郊区登记、外地或未知登记类型下采取拒绝该候选的保守处理；主城区登记也不被标注为整条路线已合法 |
| 自定义避让区 | 检查完整路线的点和线段与区域相交，包含边界接触；不只检查稀疏顶点是否落入区域 |
| 区域有效性 | 拒绝自相交、重复点、退化区域；单区限制 4 平方米至 80 平方公里，给上游 81 平方公里上限留余量 |
| 起终点与途经点 | 旧网关拒绝适用限摩区内端点；iOS 0.4.3 改为提示，0.4.4 移除限摩检查。自定义区域内仍拒绝 |
| 南京主城区禁外摩范围 | 已按用户确认采用摩途官网 `025 / 10255` 的完整 124 点图层，保留来源版本；属于第三方辅助数据 |
| 限行摄像头 | 真实南京点位尚未取得，明确显示“数据未加载”，不导入网页脚本的随机模拟点 |
| 城市高架 | iOS 0.4.2 默认开启避让，检查全部 Navi Link 的高架类型（4），未知类型不放行；依赖高德道路数据，不能只凭“不走高速”视为已避开 |
| 临时／分时管制 | 未完整收录，需结合最新通告和现场标志 |
| 道路名称缺失／变化 | 可能漏检；显示未命中不代表可以通行。道路名称匹配前的城市范围包络仅用于同名路消歧，绝不是禁行区 |

没有用矩形、行政区外接框或手绘轮廓假冒官方禁外摩边界。
已将摩途官网图层接入自动避让及完整路线检查，检索与来源见
[边界核验记录](research/NANJING_BOUNDARY_RESEARCH.md)。图层快照的获取日期不等于政策生效或记录更新日期，
仍需结合官方资料和现场标志核对。
普通驾车接口也可能排除汽车不能走而摩托车能走的路，筛选无法弥补这个路网模型差异。

## 摩途数据处理

- 固定快照：`motu-025-10255-2026-10-16.1`；[原始数据入口](https://www.motumap.com/nodata.js)。
  [共享快照与派生分区](../third_party/moto-gps-waveshare/shared/motorcycle/nanjing-motu-10255.v1.js)
  同时供 Node 和 Cloudflare Worker 打包使用，运行时不依赖摩途接口可用性。
- 124 点原始边界约 288 平方公里。以约束三角剖分及相邻合并生成 **28 个分区**，各区至多
  16 顶点、面积小于 80 平方公里；最大约 79.55 平方公里。顶点全部来自原图层，未简化或扩成矩形。
- 构建时检查分区并集与原始区域对称差为零、无重叠；运行测试另做区内、区外及凹角网格覆盖比对。
  [构建脚本](../tools/build_motu_nanjing_region.py)只解析数据字面量，不执行官网 JS，固定校验来源 SHA-256。
- 28 区加最多 4 个自定义区域刚好使用高德 32 区上限。**实际 Key 需支持对应数量的避让区域**，
  默认 1 区能力不足以保证该请求可用。上游参数错误不会触发删除区域的降级请求。
- 返回路线用完整边界复查，不依赖高德是否实际执行避让。缺少部分 step 几何时，检查完整 path
  或已验证完整的路线几何，不把残存路段片段误当整条路线。
- 摄像头接口核对见[电子眼记录](research/MOTU_CAMERA_DATA.md)；未配置登录身份、真实车牌或私有接口。

## 网关和协议

需要同时更新手机源码和自己的网关。未部署或默认占位地址不能进行真实算路。
本次没有部署外部服务，也没有配置高德 Key、iPhone 签名或新增商业接口权限。

- 路由保持 `POST /v1/route-options`、`POST /v1/routes`。
- `route_mode` 仍为 `driving`；可选 `motorcycle_options` 包含 `region`、`registration`、
  `avoid_highways`、`avoid_tolls`、`avoid_ferries`、`avoid_areas`、`waypoints`。
- iOS 0.4.2 增加布尔值 `avoid_elevated_roads`。旧客户端可省略；旧 Web 网关收到 `true` 会明确拒绝，避免在缺少道路类型时声称已检查高架。
- 区域与途经点输入为 WGS84；所有路线几何仍为 GCJ-02。
- 新响应在每条路线附带 `motorcycle_assessment`，回显精确应用的设置、资料日期、来源与覆盖说明。
- iOS 0.4.3 的 `restriction_conflicts` 保存备选路线中的限摩区域 / 桥隧冲突，用于预览与导航中的醒目提示；不改变登记类型或声称取得通行许可。
- `restriction_areas` 包含图层 ID、数据版本、GCJ-02 完整边界和登记类型适用标记，用于手机地图显示；
  `camera_data_status` 当前固定为 `unavailable`，不表示“摄像头为零”。
- iPhone 拒绝缺失区域检查信息或登记类型不匹配的结果。旧网关不能静默让新手机端退回普通汽车路线。
  进入区域冲突或上游永久参数拒绝时停止旧指引；短暂网络超时保留原有重试处理。
- 不传扩展的旧客户端保持原行为；健康检查增加 `capabilities.motorcycle_rules`，
  该能力标记不等同于真实算路成功，更不等同于完整的通行资格判定。
