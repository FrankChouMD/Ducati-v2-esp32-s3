# 当前倾角显示与 QMI8658 原型估算

2026-10-15。目标为屏幕朝上安装的 ESP32-S3-Touch-AMOLED-2.16。
画面顶部按朝向车头设计，车机须固定在车身上；支架俯仰偏置由零点校准吸收。

## 使用

- 导航页右下角、速度页下方显示 `LEAN` 和当前角度；导航页底部正中、速度页读数旁显示选定的 E 版车尾图。
  车尾图保留红色尾部、后视镜、双排气和宽后胎，素材说明见 [E 版图标](../firmware/assets/lean/README.md)。
- 摩托车图形围绕轮胎接地点按当前倾角左右转动。导航页车尾图接地点和地图投影原点均为 `(240,424)`；
  右下参考刻度同步显示左右偏移。速度页保留固定虚线与地面线，用于对照直立姿态。
  图形与数字使用同一份倾角、方向和有效状态，未增加独立模拟或估算来源。
- `L 23°` 表示左倾，`R 18°` 表示右倾，扶正显示 `0°`。
- 开机后将车扶正、静止约 2 秒，采集连续稳定样本建立零点和三轴陀螺仪偏置。
  侧撑倾斜状态不能当作零点。传感器初始化在开机动画之后开始。
  2026-10-16 接板发现静止陀螺仪零偏约 2–3°/s，原 2°/s 原始角速度门槛
  会反复打断校准。现允许原始角速度模长不超过 5°/s，并继续要求重力大小正常、
  方向连续稳定及停车条件；校准后扣除三轴零偏。实机启动日志已确认
  `Lean calibration ready`，回归测试覆盖此零偏和噪声以及较大角速度拒绝。
  同次实测还发现局部运动刷新后实体屏幕仍保留旧叉号，而 LVGL 标签已是 `0°`。
  2.16 固件现对运动更新执行整屏重绘；用户已确认叉号消失并显示数值。
  该处理增加 SPI 传输量，尚未完成动态倾斜跟随、帧率和手机连接组合验收。
- 需要重新归零时，在停车扶正后长按任一页面的倾角图形或读数区域，再保持静止约 2 秒。
- 未完成校准、传感器异常或估算参考失效时显示 `--°`，并隐藏动态摩托车、显示灰色叉号。
  导航页仍保留地图位置点；不会把无效值显示为已扶正。

## 数据链路

复用同一个 QMI8658 设备和采样任务，目标 125 Hz；加速度单位为 m/s²、陀螺仪为 °/s，
量程沿用 ±4g / ±512°/s。不会另开一个 I2C 设备读取相同传感器。
采样同时供原航向辅助与新倾角估算使用，UI 请求按现有 40 Hz 上限合并。
倾角通过本地 `NavSnapshot`、`NavPresenter` 到两个页面；无需更改 iPhone 的 BLE 数据格式。
倾角变化即使没有航向变化，也会刷新速度页和导航页。
已识别的 iPhone 演示路线不会作为真实速度参考送入倾角估算。

估算实现为本项目编写的原型互补滤波器：

1. 静止校准建立传感器到车体的前／左／上坐标系，并估计三轴零偏。
2. 用三轴陀螺仪传播车体坐标中的竖直单位向量，再由该向量计算左右横滚角。
3. 手机速度有效时，以车体速度 `v = (speed, 0, 0)` 和角速度计算 `ω × v`，
   从加速度计的比力中减去转弯运动加速度，再缓慢修正竖直向量。
   陀螺仪与加速度使用相同时间常数预滤波，减少转弯补偿的相位差。
4. 没有手机速度且尚无车辆移动证据时，大小接近 1g 且与传播姿态相容的重力可维持读数，
   手动倾斜过程不再仅因陀螺仪转速超过静止门槛而失去修正参考。
   一旦手机确认车辆在移动，速度失效后不会仅凭“小角速度”把缓弯当作停车。

手机速度超过 2 秒未更新时停止使用；没有可信修正参考再持续 2 秒后使读数失效。
IMU 数据间隔超过 160 ms、非数值或量程饱和会丢弃姿态并重新等待静止校准。
现有 25 ms 周期任务独立检查采样超时，即使传感器任务阻塞在 I2C 读取中也会使读数失效。
急加减速和冲击会使加速度修正暂时停用，短时间由陀螺仪维持。
目前输出限幅为左右 85°。前后俯仰较大不再单独触发叉号；接近竖直、
重力在横滚平面的投影过小时保留上一倾角，待姿态恢复后继续更新。
这是横滚角在该姿态下无法稳定分辨的显示处理，不代表角度仍可准确测量。
传感器断流、异常数据和修正参考超时仍显示失效提示。

## 安装轴向

静止重力能消除支架俯仰偏置，不能判断车头方向。必须配置传感器中指向画面右侧的轴：

```powershell
idf.py -C firmware -D DUCATI_IMU_SCREEN_RIGHT_AXIS=1 build
```

| 值 | 指向画面右侧的传感器轴 |
| --- | --- |
| `1` | +X，当前初始配置 |
| `-1` | -X |
| `2` | +Y |
| `-2` | -Y |

当前 +X 配置是待接板确认的安装假设，未从芯片坐标直接推断为屏幕坐标。
第一次接板必须扶正归零后缓慢向右、向左倾斜，分别确认 `R`、`L`，
并确认前后俯仰不会被当作左右倾角。方向相反或轴不对时更改该配置重新构建。

## 验证与边界

本机模拟器为两个页面提供连续的 ±32° 演示数据，页面标明演示状态；
该数据不会进入实机传感器估算。模拟器当前不转发鼠标触摸，长按校准需要实机触摸。

桌面检查覆盖持续左右转弯的合成六轴输入、转弯运动加速度补偿、安装俯仰与传感器法向反转、
静态左右倾、零偏、校准、断流、无效数据、速度过期与缓弯低角速度情况。
另检查本地倾角传到 UI、手机导航更新不清除倾角、没有航向变化仍刷新倾角，
以及两个页面的左右文字、零度、无效状态和长按校准回调。
真实 LVGL 像素导出核对了 E 版图形左倾 / 右倾、直立、85° 边界和失效后隐藏图标的显示。

尚未接板或实车验证精度。模型假定车体速度主要沿纵向，侧滑、路面坡度、振动、
手机速度延迟和安装误差仍会影响结果。手机断连时动态估算能力有限。
当前实现用于个人车机显示，尚未实现骑行日志、手机倾角回放或原车 IMU 数据读取。

- [官方组件 QMI8658 源码](https://github.com/waveshareteam/Waveshare-ESP32-components/tree/9daffb7168b3c093a330da700988a22092294eef/sensor/qmi8658)：
  实际使用仓库锁定的 2.0.0 驱动，核对本地头文件与单位设置。
- [Analog Devices AN-1057](https://www.analog.com/en/resources/app-notes/an-1057.html)：
  额外运动加速度会污染静态倾角计算，陀螺仪积分存在零偏漂移。
- [Mimmo、Zanzi：High-Performance Motorbike Lean Angle Estimation](https://arxiv.org/html/2302.06265)：
  IMU 与 GNSS 结合以及协调运动假设的参考；本实现为简化的独立原型，并未复现论文的 EKF，
  也不继承其精度、稳定性证明或赛道验证结果。
